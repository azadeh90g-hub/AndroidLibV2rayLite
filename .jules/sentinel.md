## 2024-09-06 - Path Traversal in `InitCoreEnv`
**Vulnerability:** The `InitCoreEnv` function accepted a path (`envPath`) from an external source and used it to set an environment variable without proper sanitization. This could allow an attacker to use `../` sequences to traverse the file system and point to sensitive files or directories.
**Learning:** The vulnerability existed because of a missing security validation step. The developer likely assumed the input path would always be a safe, well-formed directory string. Direct use of user-controllable input in file paths or environment variables is a common source of security flaws.
**Prevention:** All external inputs, especially those related to file paths, must be sanitized before use. For file paths, this includes canonicalizing them by converting them to absolute paths and ensuring they resolve to an expected location. A security mindset involves treating all inputs as potentially malicious until proven otherwise.
